**状态**：已拍板，按本文实现  
**日期**：2026-08-18  
**范围**：主窗口浏览 / 编辑态、解锁 HUD，以及设置里一小块倒计时外观控件  
**不在本期**：完成态勾选、标签/截止日期、通知提醒、自定义阈值编辑器、设置页整页改版

未标「已拍板」的旧口头方案以本文为准。A–H 已锁定，见 §12。

## 1. 背景与现状

Unlock Briefing 在解锁 Mac 时弹出今日待办和关键日期倒计时，主窗口（⌘⇧U）可查看、编辑，并通过 Git 同步私有仓里的 `content.json`。

当前三处展示都是**纯文本**：

| 表面 | 实现 | 现状 |
| --- | --- | --- |
| 解锁 HUD | `UnlockHUDController` / `HUDCard` | 一整块 `briefingText`，深色毛玻璃卡片，约 8 秒后消失 |
| 主窗口浏览 | `MainWindowView.viewer` | 同一段 `briefingText`，可选择复制 |
| 主窗口编辑 | `MainWindowView.editor` | 纯 `TextField` 列表，无拖曳、无优先级、无预览 |

数据模型：

```json
{
  "todos": ["完成报告初稿", "回复客户邮件"],
  "countdowns": [{ "title": "项目上线", "date": "2026-12-31" }]
}
```

- 待办是 `string[]`，顺序即数组顺序，**没有优先级、没有 id**。
- 倒计时只有 `title` + `date`（当天 00:00），**没有起始日**，展示顺序等于 JSON 顺序，**不会按剩余时间排序**。
- 倒计时文案：剩余 ≥ 7 天为「x 周 y 天」，否则「x 天 y 小时」，过期为「已到期」。

本次要把「看一眼能判断轻重缓急」做成产品能力，而不是再堆一行字。

## 2. 目标与非目标

### 2.1 目标

1. **待办可拖曳排序**，顺序写入 `content.json`，多设备同步后保持。
2. **倒计时按剩余时间自动排序**，越临近越靠前，用户不必手排。
3. **每条待办、每个倒计时是一张卡片**，不再是编号文本。
4. **待办卡片用浅色底表示优先级**（浅红 / 浅黄 / 浅绿）。
5. **倒计时外观是互斥的两种编码**（另加「不上色」）：
   - **按剩余天数整卡上色**（默认）：用命名预设切档，绿 / 黄 / 橙 / 红。
   - **进度填充**：浅色底宽度 = 剩余比例，颜色走进度四档。
   - 同一张卡**不会**同时整卡按天数上色又铺进度条。
6. 设置里可关倒计时**颜色**，但**不隐藏**「还剩 x 天 / 已到期」文字。
7. 主窗口浏览态、编辑态、解锁 HUD **共用同一套卡片语义**（字段、颜色、排序规则一致），视觉按表面适配（HUD 是深色底）。

### 2.2 非目标（本期不做）

- 待办完成勾选 / 划掉 / 归档
- 待办截止日期、重复规则、子任务
- 倒计时手动拖曳
- 自定义色板、自定义优先级个数
- **自定义 / 无限倒计时阈值编辑器**，以及按条覆盖阈值
- 设置页整页改版（只加外观模式 + 三个预设，见 §7.5）
- 同步策略、热键、解锁门闩的改动
- 把 `buildMessage` 拼出的纯文本当作主要 UI 继续演进（该函数可保留给复制/测试，但不再驱动主界面）
- 待办双写旧版字符串；待办稳定 id

## 3. 用户与使用场景

1. **解锁扫一眼（HUD，约 8 秒）**  
   不操作，只判断：今天最急的待办是哪几条、哪个日期最快到期。卡片颜色必须在不读完文字时就能传达。
2. **打开主窗口浏览**  
   看完整列表，必要时拖一下待办顺序。
3. **编辑**  
   增删改文字、改优先级、改倒计时日期；待办可拖曳；保存后 Git 同步。
4. **改倒计时观感**  
   在设置里选「不上色 / 按剩余天数 / 进度填充」，以及三个紧急度预设之一。
5. **手改 / 旧仓 `content.json`**  
   旧格式（`todos` 为字符串数组）必须仍能打开，不能空窗或丢数据。

## 4. 信息架构

主窗口浏览态与 HUD 的内容结构从「一篇文章」改为「两个区块」：

```
问候 + 日期                          （保留现有文案规则）
┌ 今日待办 ─────────────────────┐
│  [高] 卡片                     │   用户顺序（可拖）
│  [中] 卡片                     │
│  [低] 卡片                     │
└───────────────────────────────┘
┌ 关键倒计时 ───────────────────┐
│  卡片（天数整卡 或 进度填充）   │   按剩余时间自动排
│  卡片                           │
└───────────────────────────────┘
```

空态保持现有语义：「今天暂无特别安排，保持专注。」不渲染空区块标题。只有待办或只有倒计时时，只显示有数据的那一块。

## 5. 数据模型

### 5.1 待办（破坏性写入，兼容性读取）

`todos` 从 `string[]` 升级为对象数组：

```json
{
  "todos": [
    { "text": "完成报告初稿", "priority": "high" },
    { "text": "回复客户邮件", "priority": "medium" },
    { "text": "整理本周待办", "priority": "low" }
  ]
}
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `text` | string | 是 | 待办正文。空字符串在保存时丢弃（与现网 `normalizeTodos` 一致） |
| `priority` | `"high"` \| `"medium"` \| `"low"` | 否 | 缺省 = `medium` |

**读兼容**

- `"完成报告初稿"` → `{ "text": "完成报告初稿", "priority": "medium" }`
- `{ "text": "x" }` → priority = `medium`
- `{ "title": "x" }` 不作为待办（避免和倒计时对象混淆）
- 未知 `priority` → `medium`
- 仍支持整个文件是旧版纯字符串数组（只当待办）

**写约定（已拍板 A）**

- 新版本一律写对象数组。
- 旧版 App 读到对象数组会把待办解析成空。接受「升级后所有设备都要更新」，不做双写字符串过渡。

本期**不引入稳定 id**。拖曳只改数组下标。Git 冲突仍是整文件 rebase / 后写覆盖，与现网一致。

### 5.2 倒计时

继续使用 `{ title, date }`，可选 `start`。本期**不把排序结果写回 JSON**（见 6.2）。

```json
{ "title": "项目上线", "date": "2026-12-31", "start": "2026-08-18" }
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 是 | 空则保存时丢弃 |
| `date` | `YYYY-MM-DD` | 是 | 到期日，当地 00:00 |
| `start` | `YYYY-MM-DD` | 否 | 进度起点。用户**创建**该条时写入当天；旧数据缺省不回写 |

**已拍板 B**

- 进度从 `start` 当天 00:00 的 100%，线性降到 `date` 当天 00:00 的 0%。
- 用户点「+ 添加倒计时」时记录 `start = 今天`，写入 `content.json`（该条保存成功后）。
- 旧数据没有 `start`：按 **90 天窗口** 计算（`start' = date - 90d`）。若目标日距今已超过 90 天，进度钳在 100%。**不自动回写** `start`，避免无意义 Git diff。
- 非法日期：该条不展示（与现网 `formatCountdown` 返回 `nil` 一致）。
- 90 天窗口不在设置里开放（已拍板 H）。

进度：

```
remaining = max(0, target - now)
total     = max(1 second, target - start)
percent   = remaining / total          // 0...1，过期 = 0
```

`target` / `start` 均为当地日历日 00:00，与现网倒计时一致。

### 5.3 外观设置（本地 `settings.json`，不进数据仓）

| 字段 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- |
| `countdownAppearance` | `off` \| `remainingDays` \| `progressFill` | `remainingDays` | 互斥。`off` 只关颜色，文字仍在 |
| `countdownUrgencyPreset` | `relaxed` \| `standard` \| `tight` | `standard` | 仅 `remainingDays` 时生效 |

两台 Mac 的外观设置不同步，与现有其它 App 设置一致。

## 6. 交互需求

### 6.1 待办拖曳

| 项 | 约定 |
| --- | --- |
| 谁可以拖 | 仅待办。倒计时不能拖。 |
| 哪里可以拖 | 主窗口浏览态 + 编辑态。HUD 不能拖（非激活浮层，约 8 秒自动消失）。 |
| 手势 | 按住卡片拖到新位置，列表出现插入指示（线或空隙）。 |
| 落点 | 释放后数组顺序立即更新。 |
| 浏览态是否立刻落盘 | **是**（已拍板 E）。拖完即 `saveContent`；若开启了 `autoSyncOnToggle`，走与点「保存」相同的后台同步。 |
| 编辑态 | 只改 `editDrafts`，点「保存」才落盘；「取消」恢复拖之前的顺序。 |
| 优先级 | **不参与排序**。颜色只表达轻重，顺序完全由用户排。 |
| 同步中拖曳 | 允许。同步拉回新数据后，以远端 `content.json` 为准刷新列表（与现网 pull 刷新一致）。不在拖曳过程中做特殊合并。 |
| 可访问性 | 键盘：选中卡片后 `⌥↑` / `⌥↓` 上移下移一条，规则与拖曳相同。VoiceOver 朗读「待办，优先级高/中/低，第 i / n」。 |

空列表、仅 1 条：不进入拖曳。

### 6.2 倒计时自动排序

| 项 | 约定 |
| --- | --- |
| 排序键 | 距离 `date 00:00` 的剩余秒数，升序（越临近越靠上）。 |
| 已到期 | 全部排在未到期之后；已到期之间按 `date` 降序（刚过期的更靠上）。 |
| 相同 `date` | 稳定排序，保持 JSON 中的相对顺序。 |
| 是否写回 | **不写回**。JSON 顺序保持用户录入/添加顺序，避免每次打开都改文件、制造无意义 commit。 |
| 生效表面 | HUD、浏览态、编辑态预览列表都按此规则显示。 |
| 编辑态表单 | 编辑器里的输入行也按显示序排列，避免「上面改的是另一条」。添加新倒计时后，按新日期插入到正确位置。 |

## 7. 视觉需求

### 7.1 待办卡片

每条待办是一张圆角卡片，不是一行字。

| 优先级 | 色名 | 浅色底（主窗口浅色外观） | 用途 |
| --- | --- | --- | --- |
| `high` | 浅红 | 底 `#FEE2E2`，字 `#991B1B`，左边线 `#EF4444` | 今天必须做 |
| `medium` | 浅黄 | 底 `#FEF3C7`，字 `#92400E`，左边线 `#F59E0B` | 默认 |
| `low` | 浅绿 | 底 `#DCFCE7`，字 `#166534`，左边线 `#22C55E` | 可延后 |

卡片结构（浏览态）：

- 左侧 4pt 色条（强化扫视）
- 正文，最多 3 行，超出省略
- 右上角小标签：「高 / 中 / 低」（字号 caption，同色系）

编辑态同一张卡片内：

- 文本输入
- 三点优先级切换（色点或分段：高 / 中 / 低），点选立即改草稿
- 删除按钮
- 左侧或卡片空白区域为拖动手柄

深色外观 / HUD：使用同色相、更高饱和的半透明底（例如红 `rgba(239,68,68,0.22)`），正文改为浅色，保证对比度。**禁止**在深色 HUD 上直接铺主窗口那套粉彩色实心底，会发灰、发脏。

新建待办：priority = `medium`，text 为空，焦点进输入框。

### 7.2 倒计时卡片：两种互斥模式

倒计时**没有**单独的细进度条组件叠在整卡颜色之上。模式由设置选择，互斥。

文案规则沿用现网：`title` + 「还剩 x 周 y 天 / x 天 y 小时 / 已到期」。日期可另起一行小字显示原始 `date`。圆角与待办卡片一致（10–12pt）。**关颜色（`off`）时这些文字仍然显示。**

**已到期（已拍板 D）**：无论哪种上色模式，整卡浅红，并保留「已到期」文字。`off` 时已到期也不上色，只留文字。

#### 7.2.1 按剩余天数整卡上色（默认，`remainingDays`）

整张卡片一种浅色，填充宽度 100%。颜色由**剩余整天数**（与现网 `formatCountdown` 相同：`floor(剩余秒数 / 86400)`，已到期按 0）对照命名预设：

| 预设 | 存储值 | 绿 | 黄 | 橙 | 红 |
| --- | --- | --- | --- | --- | --- |
| 宽松 | `relaxed` | `> 60` | `> 14` | `> 3` | `≤ 3` |
| 标准 | `standard`（默认） | `> 30` | `> 7` | `> 0` | `≤ 0` |
| 紧张 | `tight` | `> 14` | `> 3` | `> 0` | `≤ 0` |

边界按「严格大于」左档：标准预设下剩余正好 30 天是黄，正好 7 天是橙，0 / 已到期是红。

浅色外观填充色与进度档同色相：绿 `#86EFAC`、黄 `#FDE68A`、橙 `#FDBA74`、红 `#FCA5A5`（整卡实心浅底，字用深色同色相）。

不提供自定义天数节点，也不按条覆盖。

#### 7.2.2 进度填充（`progressFill`）

整张卡片的浅色填充宽度就是进度，**不用**剩余天数整卡色。

```
┌──────────────────────────────────────────────┐
│████████████████████░░░░░░░░░░░░░░░░░░░░░░░░░ │
│  项目上线                    还剩 2 周 0 天   │
│  2026-12-31                                  │
└──────────────────────────────────────────────┘
```

- **轨道**：卡片全宽，中性浅底（浅色外观 `black 6%`，HUD `white 8%`）。
- **填充**：从左向右，宽度 = `percent`，颜色由剩余比例决定。
- **文字**：叠在填充之上，不随填充裁切。

**进度色档（已拍板 C）**

| 剩余比例 `percent` | 色 | 填充（浅色外观） |
| --- | --- | --- |
| `> 0.75` | 绿 | `#86EFAC` @ 55%，轨道仍可见 |
| `> 0.50` 且 `≤ 0.75` | 黄 | `#FDE68A` @ 60% |
| `> 0.25` 且 `≤ 0.50` | 橙 | `#FDBA74` @ 60% |
| `≤ 0.25`（含 0） | 红 | `#FCA5A5` @ 65% |

边界：`0.75` 算黄，`0.50` 算橙，`0.25` 算红。已到期走 §7.2 整卡浅红，不再画空槽。

#### 7.2.3 不上色（`off`）

中性卡片（系统 `controlBackground`），无色条、无进度填充。剩余时间文字照常。

### 7.3 两个表面的差异

| | 主窗口 | HUD |
| --- | --- | --- |
| 底 | 系统窗口 | 保持现有深色毛玻璃 |
| 卡片 | 实心浅色 | 半透明同色相 |
| 拖曳 / 改优先级 | 要 | 不要 |
| 编辑按钮 | 顶栏已有 | 保留右下角「编辑」，点完打开主窗口编辑态 |
| 高度 | 窗口可滚动 | 内容过高时 HUD 内部滚动，最大高度不超过主屏可见高度的 70% |
| 展示时长 | 常驻直到关掉 | 仍由 `showDuration` 控制，默认 8s |

问候语与日期从纯文本第一行拆成卡片列表上方的标题区，字号可略大于卡片正文。

### 7.4 编辑态整体

编辑态不再是「一组裸 TextField」，而是：

1. 待办卡片列表（可拖、可改优先级、可改文字、可删）
2. 「+ 添加待办」
3. 倒计时卡片列表（按自动序；每张可改标题 / 日期 / 可选 start；可删）
4. 「+ 添加倒计时」（创建时写入当天 `start`）
5. 「保存」「取消」「打开数据目录」保持现有位置与快捷键（保存仍是默认回车）

倒计时日期输入：保留 `YYYY-MM-DD` 文本，同时允许点选系统日期选择器。非法日期在保存时丢弃该条（与现网 normalize 一致），编辑过程中红字提示「日期无效」。

### 7.5 设置里的外观控件（允许的最小改动）

在现有设置窗增加一组，**不是**整页改版：

1. 倒计时外观：`不上色` / `按剩余天数` / `进度填充`（三选一，互斥）。
2. 当选「按剩余天数」时，显示预设：`宽松` / `标准` / `紧张`，旁注各档天数。
3. 说明文案写清：**关上色 ≠ 隐藏剩余时间文字**。

不提供增删改阈值的编辑器。

---

## 8. 逻辑与文案（保持不变的部分）

以下行为**不得回归**：

- 问候：`<12` 早上，`<18` 下午，否则晚上
- 日期标题：`yyyy年MM月dd日`
- 倒计时文案：≥7 天用周+天，否则天+小时；过期「已到期」
- 空数据：「今天暂无特别安排，保持专注。」
- HUD「编辑」必须带着已加载内容进入编辑态（`BriefingSession`），禁止再用空草稿覆盖 `content.json`
- 未配置仓库时仍显示设置引导，不渲染假数据
- Git 同步、热键、解锁门闩逻辑不改

`BriefingEngine.buildMessage` 可继续输出纯文本，供测试或将来「复制全文」。主窗口浏览和 HUD **不再把这段字符串当 UI**。

## 9. 同步、兼容、测试

### 9.1 Git

- 待办顺序、优先级、倒计时的 `start`（创建时或用户填写）都在 `content.json`，走现有 commit / pull --rebase / push。
- 自动排序不产生 diff。
- 缺 `start` 的旧条目保存后仍不写出 `start` 键。
- pretty-printed + sortedKeys 的现网写入风格保持，避免无关键序抖动。
- 外观模式与预设只在本地 `settings.json`。

### 9.2 必须覆盖的测试

在 `UnlockBriefingCoreTests` 增加纯逻辑用例（不测 SwiftUI 像素）：

1. 解析：字符串待办、对象待办、混合数组、缺 priority、非法 priority。
2. 写出：对象数组含 `text` + `priority`；空 text 被丢掉。
3. 倒计时排序：未到期升序、已到期垫后、同日稳定、非法日期剔除。
4. 进度：有 `start` 的线性计算；无 `start` 用 90 天窗口；超过窗口 = 100%；到期 = 0。
5. 进度色档：`0.76` 绿，`0.75` 黄，`0.50` 橙，`0.25` 红。
6. 剩余天数预设边界：三个预设的切档（含正好等于切点）。
7. 新倒计时带创建日 `start`；旧条目无 `start` 保存后 JSON 仍无该键。
8. 旧用例：`testParseContentUnifiedJSON`、`testHUDEditThenSaveDoesNotWipeLoadedContent`、fixture `content.json.example` 在兼容层下仍通过。

更新 `content.json.example` 与 README 中的 JSON 示例，使新克隆的数据仓一眼能看出优先级字段。

## 10. 验收标准

1. 打开主窗口，待办是独立浅色卡片，高/中/低颜色可区分；不再出现 `1. 2. 3.` 纯文本列表作为主 UI。
2. 拖动待办到新位置，关闭再打开顺序仍在；编辑态拖完点取消，顺序恢复。
3. 倒计时始终按剩余时间排；把某条日期改得更近后，它在列表中上移；`content.json` 里的数组顺序不变（除非用户增删改字段）。
4. 默认「按剩余天数」下，整卡颜色随预设切档；切到「进度填充」后改为宽度 + 进度色，不再叠天数整卡色。
5. 设置里可关上色，剩余时间文字仍在。
6. 解锁 HUD 用同一套卡片语义，8 秒内不需要交互也能读出优先级和紧迫度。
7. 只含旧格式 `todos: ["a","b"]` 的仓库打开后两条都在，优先级均为中。
8. HUD 点「编辑」再保存，不会把内容写成空。
9. 浅色 / 深色外观下文字对比可读；HUD 深色底上的卡片不发灰糊成一团。
10. 已到期倒计时整卡浅红（上色模式开启时）。
