## 1. 背景与现状

Unlock Briefing 的待办是浅色优先级卡片，浏览态可点选（供 `⌥↑/↓` 排序）并拖曳改序。拖完立刻写 `content.json`，`autoSyncOnToggle` 开启时约 3 秒后后台 `commit / pull --rebase / push`。

当前没有完成态：

| 表面 | 现状 |
| --- | --- |
| 浏览态点卡片 | 仅选中，无完成 / 归档入口 |
| 编辑态「删除」 | 从 `todos` 拿掉，文件里不再保留 |
| HUD | 约 8 秒扫一眼，除「编辑」外无交互 |
| `content.json` | 只有 `todos` + `countdowns`，没有归档区 |

`ContentStore.save` 用 `ContentDocument` 整文件重写。解析只认识已建模的键。归档若只当 JSON 旁路字段、不进模型，下一次任意保存都会把历史抹掉。

待办仍**没有稳定 id**（上期已拍板 G）。撤销必须靠「整条对象 + 原下标」快照，不能只按文案匹配。

## 2. 目标与非目标

### 2.1 目标

1. 浏览态点待办卡片，出现「归档」按钮。
2. 点归档后该条立刻从「今日待办」消失，写入 `content.json` 的**独立字段**。
3. 归档走现有 Git 同步（不是新 API）。
4. 归档后主窗口底部出现 **5 秒圆环**：绿色弧表示剩余时间，逐渐减少。
5. 倒计时内点击可收回原位；结束后圆环消失，不能再靠它撤销。

这是软删除，不是「勾选后仍留在今日列表」，也不是编辑态现有的硬删除。

### 2.2 非目标（本期不做）

- 列表上打勾、划线但仍留在「今日待办」
- 应用内「已归档」列表、搜索、按日期清理、批量恢复
- 稳定 id、`archivedAt`
- HUD 归档
- 编辑态把「删除」改成归档（删除仍是硬删）
- 倒计时卡片归档
- 改热键、解锁门闩、设置页
- 自定义撤销秒数

## 3. 建议方案

下列为 review 默认实现。与第 4 节冲突时，以拍板结果为准。

### 3.1 数据：顶层独立数组

```json
{
  "todos": [
    { "text": "回复客户邮件", "priority": "medium" }
  ],
  "archived": [
    { "text": "完成报告初稿", "priority": "high" }
  ],
  "countdowns": []
}
```

| 项 | 约定 |
| --- | --- |
| 字段名 | `archived`（只装待办） |
| 元素 | 与待办相同：`{ text, priority }`；缺 `priority` = `medium` |
| 写入顺序 | 新归档插到数组**头部**（最新在前） |
| 读兼容 | 没有该键 / `null` / 非数组 → `[]` |
| 写约定 | 始终写出该键（可为空数组 `[]`），避免时有时无的无意义 diff |
| 规范化 | 空 `text` 丢掉，与 `todos` 一致 |
| 展示 | HUD、浏览、空态**只看 `todos`**。`todos` 与倒计时都空 → 「今天暂无特别安排，保持专注。」 |
| 旧 App | 读新文件会忽略 `archived`；用旧版本再保存会写丢归档。接受「各设备都升级」，与上期待办改对象数组相同 |

不做成 `todos[].archived: true`：今日列表和历史混在一个数组里，拖曳下标、空态、多设备冲突都会变脏。

`parseContent` / `ContentDocument` / `normalize` / `content.json.example` / README 示例必须同时认识 `archived`。

### 3.2 交互：点卡片出按钮

只在**主窗口浏览态、待办卡片**上：

1. 点卡片 → 选中（已有行为），并在该卡上露出「归档」（建议右下或右上，SF Symbol `archivebox` + 文案「归档」）。
2. 同时只选中一张；点另一张，按钮跟着走。
3. 再点已选中的卡片 → **收起按钮**。
4. 点「归档」→ 该条立刻从列表移除，按钮一起消失。
5. 拖曳优先：位移超过现有阈值仍只排序，不弹出、不误点归档。归档按钮要有独立命中区，避免和 `highPriorityGesture` 拖动手势抢事件。
6. 空列表、同步引导页、编辑态：无此按钮。
7. HUD、倒计时卡片：无此按钮。

键盘归档（`Return` / `⌘↩`）可后做，本期鼠标即可。

### 3.3 撤销：底部 5 秒绿圈

归档成功后，主窗口内容区**底部中央**出现一块 overlay 浮层（不把列表顶上去）：

- 一个圆环，**剩余时间 = 绿色弧**，5 秒内从满圈线性减到 0（stroke trim `1 → 0`）。
- 圈内或右侧可写「撤销」；**点圆环或整块浮层**都回收。
- 5 秒到 → 浮层消失；**不再自动改数据**（数据在点归档时已经改完）。
- 关窗口 / 进编辑 / 再打开：浮层丢弃，**不**自动撤销。
- 归档最后一条待办切到空态时，绿圈仍必须可见。
- VoiceOver：「已归档《文案》，5 秒内点按撤销」。

```
┌─────────────────────────────────────┐
│  今日待办 …                         │
│                                     │
│              ╭───╮                  │
│              │ ↺ │  撤销            │
│              ╰───╯                  │
└─────────────────────────────────────┘
```

### 3.4 连续归档

5 秒内又归档第二条：

- 上一条**已经进 `archived`**，不再能用这个圈撤销。
- 绿圈**重置为 5 秒**，只绑定最新那条。

堆叠多个圈或「撤销最近 N 条」本期不做。

### 3.5 撤销落点

收回时插回**归档前的下标**（超出当前长度则接到末尾）。  
`text` + `priority` 原样回去。  
按快照从 `archived` 移除对应那一次写入的条目，不按文案全局去重。  
允许存在两条相同文案的待办。

### 3.6 写盘与 Git

和浏览态拖曳同一套 `persistDocument`：

| 时机 | 行为 |
| --- | --- |
| 点归档 | **立刻**改内存 + 写 `content.json`：从 `todos` 挪到 `archived` 头部 |
| 点撤销 | **立刻**写回：按快照从 `archived` 移回原下标 |
| Git | `autoSyncOnToggle` 开启时后台 `commit / pull --rebase / push` |
| 防抖 | **5 秒**（可与绿圈同长）。5 秒内撤销，远端往往只有最终态，不会先 push 归档再 push 恢复 |
| 冲突 | 与现网相同：rebase 冲突提示去数据目录；pull 成功则以远端文件刷新 |

「归档之后同步 GitHub」= 走现有同步，不阻塞等 push 成功。徽章仍是「同步中 / 已同步 / 失败」。

立刻写盘是为了崩溃不丢这次归档；同步防抖是为了误触少脏 Git 历史。

## 5. 风险

1. **没有 id**：撤销必须带「原下标 + 整条快照」。不能只按文案在 `archived` 里找，重名会找错。
2. **整文件重写**：解析/编码漏掉 `archived`，一次保存就会把历史清零。
3. **旧 App 保存**：旧版本写回会丢 `archived`。默认各设备升级。
4. **点按 vs 拖曳**：归档按钮必须独立命中，避免「想归档却拖走了」。
5. **同步中 pull 刷新**：归档后、push 前若另一次 sync 拉回旧文件，列表可能「诈尸」。沿用现有「远端为准」；防抖可减轻。
6. **空态闪烁**：归档最后一条待办会切到空文案，撤销后再回来。绿圈要在空态时也看得到。

## 6. 逻辑与测试

纯逻辑放 `UnlockBriefingCore`（归档 / 撤销变换、解析写出），圆环动画只在 App 层。

必须覆盖：

1. 解析：无 `archived`、空数组、对象数组、字符串混入、缺 / 非法 `priority`。
2. 写出：始终带 `archived` 键；空 text 被丢掉；pretty-printed + sortedKeys 风格不变。
3. 归档变换：指定下标从 `todos` 移除并插入 `archived` 头部；返回可供撤销的快照。
4. 撤销变换：按快照插回原下标；原下标越界则追加末尾；只移除对应那一条，不误删同文案的其它归档。
5. 展示：`presentation` / HUD / 空态忽略 `archived`。
6. 旧用例：`testParseContentUnifiedJSON`、HUD 编辑再保存不清空、`content.json.example` 仍通过。

同步策略不单测 Git 本身，行为与浏览态拖曳落盘一致即可。

## 7. 验收标准

1. 浏览态点待办卡，出现「归档」；点它后该卡从「今日待办」消失。
2. `content.json` 里该条出现在 `archived` 数组头部，`todos` 里没有。
3. 开了自动同步时，防抖结束后能在 Git 远程看到这次变更。
4. 归档后底部出现绿圈，约 5 秒内绿色弧减完后消失。
5. 绿圈消失前点它，该条回到原来的位置，并从 `archived` 移除。
6. 5 秒后再点原位置，不能再撤。
7. HUD 和解锁弹层仍只显示未归档待办；全部归档且无倒计时显示空态。
8. 没有 `archived` 的旧 `content.json` 仍能打开；保存后带上 `"archived": []`（或按拍板后的写约定）。
9. 编辑态「删除」仍是从文件里去掉，不进 `archived`。
10. 浅色 / 深色外观下归档按钮和绿圈可读、可点。
